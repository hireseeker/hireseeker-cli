# Границы CLI: контракт, процессы и артефакт

- Перед изменением поиска проверить оба consumers схемы: `vacancy search` и `filters guide`. Проверять структуру, но возвращать исходный JSON после валидации: дополнительные поля API сохраняются.
- `exists(SKILL.md)` не доказывает корректность skill. Общий preflight источника должен проверять обычный непустой файл и дерево до создания целевого каталога, в `init` — до запуска npm. Локальный дефект пакета не классифицировать как сетевую ошибку.
- Тест npm timeout/cancel должен запускать настоящее дерево с процессом, игнорирующим SIGTERM, и проверять прекращение heartbeat. Отказ инструмента остановки — отдельный failure path; успехом его не считать.
- Подмена executable должна попадать в окружение того процесса, который его запускает. Пустой PATH может активировать fallback resolver; для missing-command fixture использовать непустой пустой каталог и учитывать Windows `Path`/`PATH`.
- Перед CI использовать только дешёвую `npm run syntax`: parser ловит повреждённые строковые литералы без build/typecheck. Зависимые операции выполнять с проверкой exit code; ошибка первого шага прекращает цепочку.
- Receipt проверяет идентичность выбранного tarball, а не доверие к источнику. Проверенный источник — зелёный exact-SHA CI; перед установкой или публикацией использовать `npm run artifact:check -- DIRECTORY FULL_COMMIT_SHA`. Hash mismatch останавливает дальнейшие действия.
- Runtime evidence должно относиться к установленному CI-tarball. Не заменять его локально пересобранным dist и не повторять сборку для проверки архива. Рецепт: [разработка](../../docs/development.md), [выпуск](../../docs/release.md).

Правила бренда, отдельной GitHub-авторизации и запрет публикации без запроса находятся в [AGENTS.md](../../AGENTS.md); здесь их не дублируем.

- При автоопределении агентов проверить тип каталога, а не только exists. Ошибка чтения одной конфигурации должна иметь локальную диагностику и не мешать независимым установкам остальных агентов.
